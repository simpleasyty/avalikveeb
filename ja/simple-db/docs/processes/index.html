はじめに

バックグラウンド処理

長い SQL 実行やテンプレート処理をバックグラウンドで進めながら作業を続けます。

バックグラウンドで実行する

複数の SQL 文の実行にはバックグラウンドオプションを使用します。ジョブが登録され、Processes で進捗を確認しながら Studio で別の作業を続けられます。テンプレートのインストールと削除もバックグラウンドジョブを使用します。

並行して進められること

ジョブの処理中も作業を続けられます。1 つの SQL ジョブ内では文は同時ではなく順番に実行されます。バックグラウンド処理もインストールの Forge 上限を共有し、データベース容量やトランザクション機能を追加しません。同じテーブルへの同時変更は避けてください。

再試行の前に失敗を確認する

Processes でジョブを開き、状態と文ごとの結果を確認します。必要に応じて表示されるキャンセルや再試行を使用してください。キャンセルしても完了した文は取り消されません。データを追加・変更するスクリプトを再試行する前に、成功済みの処理を確認してください。

アップロード、実行、部分完了を区別する

大きい SQL はエディターの外で準備し、分割してアップロードします。アップロードパネルで進捗を確認し、キュー登録前にキャンセルできます。その後 Processes が実行進捗、完了文数、影響行数、最後または失敗した文を表示します。アップロード完了と実行完了は別です。最初の SQL エラーで停止し、既に確定した変更は残ります。プラットフォーム中断時は最後の書き込みが不確定になる場合があります。

関連ガイド

  • データ所在地Simple DB のデータ保存先と、Forge のデータ所在地と Confluence サイトの関係を確認します。
  • Forge での保存Simple DB のどのデータが Forge SQL と Forge KVS に保存されるかを確認します。
  • データベースの信頼性と SQL の制限Atlassian が管理するデータベースの分離、バックアップ、インストールごとの上限を確認します。
  • SQL とデータのインポート・エクスポート互換性のある SQL スクリプトを Studio に読み込み、SQL テキストやクエリ結果を出力します。
  • データベースオブジェクトへのアクセスを管理テーブル、ビュー、クエリ、プロジェクトの読み取りと変更を管理します。
