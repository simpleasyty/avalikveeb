ページマクロとビュー

再利用する結果ビューを作成・管理する

プレビュー、表示、列を設定し、テーブルやクエリに便利な表示を保存します。

1つのソースに複数の表示

結果ビューはクエリ結果の名前付き表示であり、CREATE VIEW や行のコピーではありません。同じソースに運用担当者用の詳細テーブルと管理者用の要約表示を用意できます。名前と任意の説明を付け、用途を分かりやすくします。

読み取り専用プレビューで設定する

クエリを実行して New view または結果ビュータブの設定を開きます。Name、Description、Visualization を変更すると、読み込まれた行で表示を確認できます。プレビュー内のデータは読み取り専用です。Table は表形式の結果に対応し、Cards、Metrics、Chart はインストールでの有効化とソースの適合性に依存します。

Display：閲覧者の操作

Display では Search & Filter bar、初期 Search/Filter モード、保存する条件、Hide for readers、Sorting、Grouping、Row numbering、Page size を設定します。Viewer actions には利用可能な Refresh と Download as CSV があります。グループ化は編集を無効にします。検索、フィルター、ページ分割の対象は読み込んだ結果であり、データベース全体ではありません。

Columns：表示する内容

Columns で順序、表示見出し、Visible/Hidden、フィールド型と形式を設定します。Data field は SQL 結果の列のままです。見出しや通貨形式を変更しても SQL スキーマは変わりません。列やフィルター操作の非表示はアクセス制御ではありません。

Editing：書き込み可能な結果のみ

ソースと主キーの由来が CRUD に適合すると、Editing に Edit rows・Insert rows の Off、Inline、Form と Allow delete が表示されます。Cards はインライン・フォーム編集とフォームでの追加に対応します。テーブルのグループ化と編集は同時に使えません。操作の表示は権限を付与せず、書き込みには閲覧者のソース権限が必要です。商談段階ごとの件数など、集計結果は読み取り専用です。

Apply、保存、既定の表示

Apply は現在のビューを更新しますが、ドラフトをソースへ自動保存しません。ビュータブの保存操作で、設定と共にクエリやテーブルへ保存します。保存済み版を解除してもローカルのドラフトは残ります。ソースへの保存には Write が必要で、マクロの保存とは別の操作です。

Properties → Result views で保存済みの名前、説明、表示形式を確認します。Write があれば並べ替え、Set as default、保存済み候補の削除ができます。既定のビューが最初に開きます。Admin は Restrictions とスキーマの管理権限であり、表示の保存や公開を代行するものではありません。

ページで再利用する

マクロエディターで保存済みソースと利用可能な結果ビューを選び、パラメーターを確認して保存します。データを複製せずに同じソースを複数ページで使用できます。閲覧者のフィルターは読み込んだ結果に作用し、取得する行は SQL の WHERE、ORDER BY、LIMIT が決めます。

マクロエディターから共有ビューを管理する

選択したソースへの Write 権限がある場合、New view で現在のレイアウトを再利用可能なソースビューとして保存できます。保存済みビューの名前、説明、可視化を編集したり、確認後に削除したりできます。これらはマクロの保存とは別に共有ソースの設定を変更します。変更する前に、同じビューを使用する他のページを確認してください。
