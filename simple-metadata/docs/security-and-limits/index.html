Security, storage and limits

Where Simple Metadata stores data and the limits to plan around.

SIMPLE METADATA

Storage and personal data

Simple Metadata runs on Atlassian Forge. Live schemas, entries and the report index use Forge SQL; entry history and schema revisions use Forge KVS.

Customer-entered metadata can contain personal information, such as names, email addresses or contact details. This content is stored within Atlassian-hosted infrastructure, without being sent to a Simpleasyty-operated external data store.

Atlassian user references

User references are stored as accountIds. Display names and avatars are retrieved from Atlassian at runtime rather than persisted separately as profile data.

History and deletion

Previous metadata values are retained as entry snapshots in Forge KVS for 90 days. Snapshots retain their schema version so historical values remain interpretable.

Deleting an entry removes its current metadata and attempts to remove all retained historical versions. If history cleanup fails, those versions may remain until their 90-day expiry. Deleting a schema schedules removal of its SQL data and retained entry history; follow progress in Processes.

Usage limits

  • List and report requests return up to 500 entries. Use focused filters for larger datasets.
  • Fields must be indexed before they can be used for report filters. Reports use the schema’s field definitions and filter rules.

Troubleshooting

For a missing schema, check space, label and group eligibility. For missing filter results, check that the field is indexed and affected entries have been saved or reconciled.
