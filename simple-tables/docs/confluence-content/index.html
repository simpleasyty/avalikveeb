Confluence Content

Build a live table from the Confluence content your team already creates. Search pages, blog posts, attachments, and other supported content, then choose the fields readers need in one useful view.

SIMPLE TABLE MACRO

SEARCH CONFLUENCE. MAKE THE RESULT USEFUL.

A live view of the content that matters to your team.

Start with the pages your team already manages, narrow the result, and turn the returned content into an interactive table without exporting it elsewhere.

Find the right content

Use type, space, label, or text to focus the result. Use advanced CQL when your query needs more precision.

Choose the reader’s view

Select fields such as title, space, creator, status, or last updated before you publish.

Keep the view live

The saved query is run again when the table loads, so matching Confluence content remains current.

Turn a Confluence search into a table

Each row is one matching piece of Confluence content. The query defines what belongs in the view; the selected fields define what readers see.

1

Choose Confluence Content

Add a Simple Table macro, open Integrations, and select Confluence Content.

2

Focus the search

Use the filters for content type, space, label, or text. Choose how many results to return, then select Find content.

3

Choose columns and publish

Review the results, select the fields to display, then configure the table with sorting, filters, grouping, or formatting before publishing.

TIP

This source searches across Confluence and creates a table from the returned content. For a table that already exists on one page, use Simple Table with Body and Native Confluence tables instead.

Example: a live project register

A delivery team uses a shared label on project pages across several spaces.

In Confluence
Every project page is maintained by its team, with its own title, owner, status, and update history.
→
In the register
One Confluence Content table searches for that label and shows the title, space, last updater, and last updated date in a sortable overview.

What the table can show

The default fields include title and content type. You can also select fields such as space, version, created date, last updated date, creator, last updater, and status. Attachment-specific fields appear when your query returns attachments.

A useful, bounded search

  • The editor starts with 50 results. You can choose from 1 to 1,000 results when the intended view needs a different size.
  • The query and selected visible columns are saved with the macro configuration. The table uses the current matching content when it loads.
  • Use Page Properties instead when you need the key/value data inside a Page Properties macro, rather than the normal fields of Confluence content.
