Privacy Policy

At Simpleasyty, we believe privacy should be as simple and clear as the products we build. Our apps can store customer-provided personal data within Atlassian’s infrastructure.

Customer-provided metadata and table content may contain personal information, such as names, email addresses or other contact details. Storing this content is storage of personal data even when it was entered by a customer rather than populated from an Atlassian profile. Storage within Atlassian-hosted infrastructure does not mean that the content is sent to or stored in a Simpleasyty-operated external backend.

Simple Metadata uses Forge SQL/KVS and retains historical metadata values for 90 days. Atlassian user references are stored as accountIds; display names and avatars are retrieved from Atlassian at runtime rather than persisted separately as profile data. Simple Tables stores customer-provided content using Page Content, Attachment or Atlassian Store (Forge Storage), depending on the configured storage method.

Core app functionality runs on Atlassian Forge and uses Confluence and Forge storage for customer content. Product analytics has the separate external data flow described below.

Product analytics

Simple Tables and Simple Metadata send limited product usage data to Amplitude Analytics to understand feature adoption, diagnose product issues, and analyse use across sites and app installations.

Before initializing analytics, the app transforms the Atlassian accountId into a deterministic SHA-256 user identifier. The raw accountId is not sent to Amplitude. The same account produces the same analytics identifier in both apps. This is pseudonymisation: it allows activity to be associated with a user over time, so we do not describe it as anonymous data.

What product analytics collects

Product analytics does not send table cell values, metadata entry values, page titles, attachment contents, names, email addresses, search text or formulas as product event properties. Automatic page, session, form and download events, autocapture and remote configuration are disabled.

  • Explicit usage events, such as macro rendering, configuration saves and feature actions, with technical context including app version, environment, locale, data-source categories and aggregate row or column counts.
  • The site base URL and, for Simple Tables events where applicable, page and macro identifiers. The event contract differs between the two apps.
  • The user profile properties cloud_ids and installation_ids: distinct site IDs and app installation IDs supplied by Forge and observed while the user uses the app. These lists can retain previously observed sites or installations; they do not describe current membership or permissions.
  • The browser SDK also adds technical information such as device and session identifiers, browser information, language and timestamps. Requests to Amplitude expose the network IP address to that provider; the current SDK configuration also allows IP-based enrichment.

Destination and administrator controls

Amplitude is an external analytics provider. The app SDK is configured to use Amplitude’s EU ingestion endpoint. This analytics flow is separate from the Confluence and Forge storage used for customer content; the content’s Atlassian data residency setting does not configure Amplitude.

Analytics egress is declared in the Forge app manifest. Administrators can disable analytics access through the controls provided by Atlassian. The app handles unavailable analytics without preventing its core functions from opening or saving.

Browser storage

The Amplitude browser SDK may use cookies or browser storage in the app iframe to retain analytics identity and delivery state, subject to browser restrictions. The cookieless Umami analytics described in our Cookie Policy applies to the public website; it does not describe product analytics.

Retention and privacy requests

Event data in the Simple Tables and Simple Metadata Amplitude projects has a 36-month Time to Live (TTL), measured from ingestion. Amplitude enforces expiry through scheduled deletion jobs. This period supports comparisons of product use across years. For information about the retention applicable to your data, or to request access, correction or deletion, contact legal@simpleasyty.com. We verify requests and handle them under the applicable requirements.

Event TTL does not by itself establish an expiry period for user profiles or each value in cloud_ids and installation_ids. Deleting a macro or uninstalling an app does not automatically delete analytics already collected by Amplitude. Analytics deletion must also cover the relevant Amplitude user profile and events in each affected app project.

Simpleasyty is committed to privacy by design and aims to meet relevant data protection standards, including the General Data Protection Regulation (GDPR).

For any questions or concerns regarding data and privacy, contact us at legal@simpleasyty.com. You can also review our Terms of Use and Security.
